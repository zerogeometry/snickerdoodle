# Gelato (gelato.com) as a cheaper print-on-demand maker for a small UK children's-art gift shop

Research date: 26 November 2026. All Gelato prices below were read on gelato.com's public UK catalog with the site set to "United Kingdom · GBP". No login was needed for the catalog prices; nothing was signed up for, no forms were filled in and no images were uploaded. gelato.com blocks plain fetch tools (HTTP 403), so pages were read in a real browser. Catalog prices are labelled "excl. VAT" on the page. Each product page has a "Regional pricing / Economy" table with the columns *Product / Shipping first product / Shipping additional product*. The UK row of that table is quoted as **product £ / first-item ship £ / each extra item £**.

Important reading notes:
- On several paper products (cards, calendars) the price shown did not change when I picked a different size or envelope, even though the Product UID did change. So treat those figures as **"from" prices for the cheapest variant** until a dashboard quote confirms them. On framed posters the price *did* change with each size (figures below are per size).
- The category list pages sometimes show a different "From" price from the product page itself (e.g. classic matte framed poster: list "From £10.74", while the product page shows the 13×18 cm ready-to-hang at £13.12; wall calendars: list "From £7.36", product page £6.04). Both are quoted where they matter. A dashboard quote, which needs an account, is the only definitive check.
- Browser note for the coordinator: on gelato.com's cookie banner I opened "Cookies Settings" and tried to switch off the performance and functional cookies, then confirmed. Analytics and ad trackers still fired afterwards, so consent was probably recorded as accepted in the built-in browser profile. Nothing personal was entered.

## Q4: Does Gelato combine products from different partners into one parcel, and how does it route?

### Takeaway
No. Gelato tries to fulfil a whole order from one facility, but if items are best made in different places it **splits the order into separate parcels**, each charged and tracked separately. Routing is by algorithm, usually to the nearest production centre, but sometimes cross-border.

### Cited Findings
- "If products are best made in different locations, Gelato splits the order into multiple shipments", e.g. #1068 (1/2) and (2/2). Each shipment is priced separately, and the dashboard shows "Economy delivery (Multiple print locations)" as the sum. Each shipment has its own tracking number, and the end customer gets a confirmation email per parcel. Segments must be cancelled one by one. Inserts and labels go into each qualifying shipment. Last updated 30 Oct 2025 — [Gelato help: multiple print locations](https://support.gelato.com/en/articles/8996103-what-happens-when-an-order-is-sent-to-multiple-print-locations)
- API: "We always try to fulfill your order from a single fulfillment facility, if this is not possible multiple quotes will be returned" (`allowMultipleQuotes`, default true); each quote carries `fulfillmentCountry`, `shipmentMethods` and `numberOfParcels` — [API quote order](https://dashboard.gelato.com/docs/orders/v4/quote/)
- "The country in which each order is fulfilled is carefully selected by our advanced routing algorithm… In most cases, products are fulfilled at the closest production center. Sometimes due to reasons such as stock availability, orders may be shipped internationally even if a fulfillment center exists within the same country." — [tough case page](https://www.gelato.com/uk/custom/phone-cases/tough-case)
- "Gelato sends the order to the production partner nearest to your customer" — [UK pricing page](https://www.gelato.com/uk/pricing)
- Network claims: "250+ production partners in 32 countries", "60+ logistics partners" — [shipping & delivery](https://www.gelato.com/uk/shipping-and-delivery). The same page's FAQ says "over 140 production partners" (internal inconsistency).

### Inferences
- A typical basket (framed print + mug + cards) may arrive as 2–3 parcels with 2–3 shipping charges. Per-extra-item rates only apply to items in the *same* shipment, so the shop's shipping model must assume per-parcel charges unless a quote shows one facility.

### Gaps
- Which UK facility makes which product category (and so which combinations ship together): not published; only a live API quote would show it.

## Q5: API fit for a custom Next.js shop

### Takeaway
Gelato has a mature REST API (Order v4: create, quote, draft, patch, cancel, search; product catalog, price, stock and shipment-method endpoints; webhooks). Print files are passed **by URL** (PDF/PNG/JPEG/TIFF/SVG), with named print areas (`default`, `front`, `back`, `inside` for folded cards, sleeves and necks) and multi-page PDFs for calendars and cards. Integration effort for a custom shop is moderate. One fit issue: Gelato **downloads the file from a URL you give it**, so the shop would need to mint a short-lived signed URL per order.

### Cited Findings
- Create order: `POST https://order.gelatoapis.com/v4/orders`, header `X-API-KEY`; `orderType` (order or draft), `orderReferenceId`, `customerReferenceId`, `currency`, `items[]` (`productUid`, `files[]`, `quantity`), `shipmentMethodUid`, `shippingAddress`, `returnAddress`, `metadata` — [API create order](https://dashboard.gelato.com/docs/orders/v4/create/)
- `shipmentMethodUid` "accepts values such as normal, standard, express, or a shipmentMethodUid value returned in the Quote API… If no value is provided, the system will select the cheapest available shipping method" — [API create order](https://dashboard.gelato.com/docs/orders/v4/create/)
- Files: "Supported file formats are: PDF, PNG, TIFF, SVG and JPEG. For PDF files, please use one of the compatible PDF/X standards". File types: `default` ("for apparel, it is the front, while for folded cards, it is the cover+back pages… If you provide a multipage PDF, the number of pages should match the print areas"), `front`, `back`, `neck-inner`, `neck-outer`, `sleeve-left`, `sleeve-right`, **`inside` ("Print the file on the inner pages of folded cards")**, embroidery types. `pageCount` covers multi-page products. `url` is "A URL from where the file can be downloaded" — [API create order](https://dashboard.gelato.com/docs/orders/v4/create/)
- "For products with more than one print area, such as Photo Books, Greeting Cards, Calendars, and Apparel, a single multi-page PDF file can be provided or you can provide a single page raster file for each print area" — [API get started](https://dashboard.gelato.com/docs/get-started/)
- Quote: `POST https://order.gelatoapis.com/v4/orders:quote` returns quotes per fulfilment country, each with shipment methods, price, min/max delivery days and incoterms — [API quote order](https://dashboard.gelato.com/docs/orders/v4/quote/)
- Other endpoints in the docs' navigation: Get/Search/Cancel order, Patch draft order, Delete draft; Products: List catalogs, Get catalog, Search products, Get product, Cover dimensions, **Price**, Stock availability; Shipment: Methods; Ecommerce product and template endpoints — [API docs navigation](https://dashboard.gelato.com/docs/orders/v4/create/)
- Order statuses: created, uploading, passed, in_production, printed, draft, failed, canceled, pending_approval, on_hold, etc. Cancel is only possible before production — [How orders work](https://dashboard.gelato.com/docs/orders/order_details/)
- Webhooks: events **Order Status Updated**, **Order Item Status Updated** (incl. printed or error), **Order Item Tracking Code Updated**. JSON POST over TLS; expects a 2xx; "Webhooks will try to send the request data 3 times, with 5 seconds delay between each try". The payload includes `fulfillmentCountry` and `fulfillmentFacilityId` per item. The webhook URL is configured in the API portal — [API webhooks](https://dashboard.gelato.com/docs/webhooks/). I found no mention of webhook signature verification on that page.
- Order responses include Gelato-hosted `processedFileUrl` and preview URLs on `gelato-api-live.s3.eu-west-1.amazonaws.com` (example data) — [API create order](https://dashboard.gelato.com/docs/orders/v4/create/)

### Inferences
- Per-variant print areas are encoded in the Product UID (e.g. framed poster size, mug colour, card fold/paper/envelope). The shop would map each SKU to a Gelato UID and render print files at Gelato's required pixel sizes (via the "Cover dimensions" / product endpoints).
- Webhook hardening: with no visible signing, only 3 retries 5 s apart and possible duplicates, the shop would need its own idempotency and a polling fallback (Get order). The project rules require verified-signature webhooks, so this needs checking with Gelato (e.g. a secret in the URL, or IP allow-listing).
- Effort estimate (inference): a quote → create → webhook flow for about 9 product types, plus print-file renderers (calendar multi-page PDF; card cover/back and inside), is similar to integrating any other POD order API — days, not weeks — but SKU mapping and file-spec work per product dominate.

### Gaps
- API rate limits, sandbox/test mode, and webhook authentication: not seen in the pages read.
- Whether Gelato keeps a copy of the downloaded print file, and for how long (see Q7).

## Q7: Data protection, headline only

### Takeaway
Gelato (Oslo, Norway) says personal data is stored with GDPR-compliant cloud providers **in the US and Europe**, and is passed to local print partners (some outside the EU) under its DPA plus EU SCCs. API example responses show files on AWS S3 **eu-west-1 (Ireland)**. A published DPA page exists but is titled for GelatoConnect. No print-file retention period was found.

### Cited Findings
- "Your Personal Data will be transmitted, uploaded, transferred, stored, or backed up at Gelato's servers with our GDPR compliant cloud providers in the United States and Europe… This may mean a transfer of your personal data out of EU." "Gelato will transfer personal data to countries outside of EU due to our business model with printing locally…"; printers and third parties sign "our Data Processing Agreement and the EU Standard Contractual Clauses" — [Gelato privacy policy (UK)](https://www.gelato.com/uk/legal/privacy)
- DPA page: "Appendix 1 – Data Processing Agreement" for GelatoConnect; it notes personal data "may be included in the design files you upload" — [DPA for GelatoConnect](https://www.gelato.com/au/legal/data-processing-agreement-for-gelatoconnect) (search snippet; not opened)
- Trust page mentions AWS hosting with EU data-residency options and retention/disposal policies, with no durations — [gelato.com/trust](https://gelato.com/trust) (search snippet)
- Manufacturer contact on product pages: Gelato, Dronning Eufemias gate 8, 0191 Oslo, Norway — [tough case page](https://www.gelato.com/uk/custom/phone-cases/tough-case)
- Processed files and previews in API examples sit on `gelato-api-live.s3.eu-west-1.amazonaws.com` — [API create order](https://dashboard.gelato.com/docs/orders/v4/create/)

### Inferences
- For children's drawings this means: US storage is possible under the privacy policy, the image goes to whichever partner is routed (possibly non-UK), and there is no stated deletion window. These are points for the dedicated data-protection researcher.
