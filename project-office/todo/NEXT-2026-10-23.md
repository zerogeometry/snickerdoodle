### Founder-reported (22 Oct, late) — to fix
**P1 · Socks: zooming out the repeat shrinks the drawing but doesn't add copies.** ✅ FIXED 23 Oct (the motif follows the zoom, rows follow the motif; the pinch re-draws the repeat live).
All three repeat products (socks, wrapping paper, tea towel) share one layout (`src/server/print/pattern-geometry.ts`)
and one live preview (`src/app/studio/position/PatternRepeat.tsx`). Two things combine:
1. **During the pinch** the preview just scales the already-drawn picture (`--gk`), so the drawing shrinks and the
   edges empty out. It only re-tiles on release. This is the same on all three products.
2. **The print file adds copies in coarse jumps on the ankle sock.** The column count must be EVEN (so a half-drop
   repeat meets itself where a sock wraps round), and the motif is sized to fill its cell, not taken from the zoom. On
   the narrow ankle print (300 mm) that means:

   | zoom | 100–90% | 80–50% | 40% | 34% (min) |
   |---|---|---|---|---|
   | ankle sock | 2×2 · 108 mm | 4×4 · 54 mm | 6×6 · 36 mm | 8×8 · 27 mm |
   | tea towel (695 mm) | 6×4 · 83 mm | 6×4 → 12×8 in steps every ~10% | 14×9 · 36 mm | 16×11 · 30 mm |

   So on the ankle sock, zooming anywhere from 80% to 50% gives exactly the same print. Wrapping paper and the tea
   towel are wider, so they step every ~10% and feel right.

**Fix outline:**
- Re-tile live during the pinch: draw the repeat at the gesture's scale instead of CSS-scaling the picture.
- Make the steps fine on socks. Check whether the ankle print (`printTo: ['front']`) actually wraps. If it doesn't,
  drop the even-column rule for it. Either way, let the motif size follow the zoom more closely, so every zoom step
  visibly changes the print.
- Keep preview == print (the same `patternLayout` everywhere) and the per-motif DPI gate. Unit-test that the count
  rises monotonically as the zoom falls, on every pattern product.

**P2 · Socks: the two socks in the photo must match.** ✅ FIXED 23 Oct (one print area per sock, the same print file in each, never mirrored). **Founder: run `seed.ps1`** (it applies migration 0042 and re-seeds the mockups from your sock photos).
- **The print file is right.** It's ONE sock's print map, and Prodigi prints the same file on both socks of the pair.

**Fix outline:**

  (`print_quad` → a list; a single quad stays valid for every other product), with a mockup cache bump.
- Check against Prodigi's sock template whether the second sock is printed MIRRORED (a left/right pair). If so,
  flip it in the mockup to match.
- Test: on a synthetic two-sock printmap, both socks' pixels match (one mirrored if that applies), so preview ==
  print. Then the founder re-seeds the mockups (`seed.ps1 -Only mockups`), because the sock photos live on their
  computer.
